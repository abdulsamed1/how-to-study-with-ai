# Advanced engineering coverage orientation

This page is a broad topic-to-book orientation, not a reading checklist, source ranking, or claim that any listed book is the only suitable source. It assigns no chapters or pages.

For any topic, search the full Project Sources library. Look across all relevant books, PDFs, papers, official documentation, and other material. Use the most useful sources even when they are not listed here. Follow cross-references and compare different authors' treatment of the same problem.

## Optional book starting points

- **Data systems, storage, replication, consistency, and stream processing:** *Designing Data-Intensive Applications* — Martin Kleppmann and Chris Riccomini (S19).
- **Architecture characteristics, decomposition, components, and design trade-offs:** *Fundamentals of Software Architecture* — Mark Richards and Neal Ford (S20); *Software Architecture: The Hard Parts* — Neal Ford, Mark Richards, Pramod Sadalage, and Zhamak Dehghani (S38).
- **Service boundaries, integration, and evolution:** *Building Microservices* — Sam Newman (S26).
- **Distributed-system models, failures, coordination, and resilience:** *Understanding Distributed Systems* — Roberto Vitillo (S27).
- **Scalability, performance, and distributed architecture:** *Foundations of Scalable Systems* — Ian Gorton (S28).
- **Distributed-system implementation patterns:** *Designing Distributed Systems* — Brendan Burns (S29).

These are starting points only. Do not limit a lesson to this list, the unit's source tags, or a particular chapter/page. Search for the most relevant and detailed treatment available in the Project Sources and supplement it with current primary sources when needed.

## Topic map

| Engineering area | Topics to explore |
|---|---|
| Data and persistence | Data models, relational design, constraints, integrity, storage, indexing, transactions, replication, consistency, streams |
| Software architecture | Components, boundaries, coupling, cohesion, architecture characteristics, decision trade-offs, fitness functions |
| Distributed systems | Partial failure, time, ordering, coordination, consensus, messaging, idempotency, workflows |
| Performance and reliability | Capacity, queues, bottlenecks, caching, retries, overload, observability, recovery |
| Production delivery | Testing, security, deployment, rollback, operational ownership, measured outcomes |

The journey units define the capabilities to develop. This page only suggests places to look for deeper explanations; it does not prescribe how much of a book to read or which source must be used.
