# Capability and claims policy

This file is a short integrity rule, not a learner-progress database.

- **CLAIM-01 — Learner-owned progression:** The learner declares the current journey, unit, and part. The mentor does not maintain, infer, or persist a lesson-completion ledger.
- **CLAIM-02 — No achievement by exposure:** Reading, watching, a correct immediate answer, or generated code alone does not justify a broad skill or mastery claim.
- **CLAIM-03 — Keep real artifacts:** Tests, source code, ADRs, evaluation reports, traces, deployment records, runbooks, and measured outcomes remain part of the capstone when the mission requires them. These are engineering deliverables, not personal progress files.
- **CLAIM-04 — Distinguish environments:** Label work as exercise, local demo, working system, staging deployment, or real production outcome. Do not turn a lab, stub, rehearsal, or simulated incident into production experience.
- **CLAIM-05 — No invented ownership or impact:** Do not claim production deployment, users, metrics, business results, or ownership unless the actual project artifacts and provenance support the exact statement.
- **CLAIM-06 — No progress synchronization:** Do not create learning records, session exports, retrieval-target files, or status updates in the repository unless the learner explicitly requests a separate written artifact.
