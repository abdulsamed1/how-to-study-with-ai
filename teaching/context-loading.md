# 4. Loading context and choosing the journey

## 4. Loading context and choosing the journey

Read only what the session needs: `../workspace/mission.md`, newest learning records, `../workspace/evidence.md`, the active journey's rules and current phase, relevant project files, relevant casebook entries. Read a large reference file by section: locate the heading or ID with `grep`, then read only that range. Do not load every phase of a journey or every row of a catalog for one lesson.

**Active journey.** It is the journey whose goal matches `../workspace/mission.md` and the user's request (for the FDE mission, `../journeys/fde/journey-overview.md`). This file is the single canonical FDE journey and contains both the outcome map and the detailed engineering sequence. For a lesson, read the journey rules, gate table, route layer, and the one phase being taught; open other phases or sections only when the task needs them. Supporting maps (the performance map) are opened only when the active journey names them or the user asks for them. A journey with an interview deadline becomes active only when the user names that interview. Never pick a map because it is the most detailed. If two journeys fit, ask once.

**Readiness check, every time the user asks to start or continue.**
1. Read the active journey's rules, gates, and route layer; locate the next unit from the unit list and read only the phase section needed for the selected mode.
2. Find the next lesson unit. A usable unit has an ID, a priority, source tags, and a named evidence or NO-EVIDENCE status.
3. If no such unit exists, or it names no sources, do not teach a generic lesson. Sources marked found or unchecked are not a reason to rebuild the map: open them while preparing the lesson through [branch-map and general-topic routing](branch-map-protocol.md) (P§10). Build the branch map first, show it compactly, get the user's confirmation, then teach its first unit.
4. State in one line which journey and unit you are teaching.

5. If the active journey carries a route overlay or milestone track (for example `../journeys/fde/journey-overview.md` §10), read it as a milestone and route layer only: it never overrides hard prerequisites, gates, or proof criteria, and it does not change unit IDs or file order.

If `../workspace/mission.md` is missing: interview the user (at most two questions), draft it from the journey file, confirm, then write it (modes B and C: after confirmation, include it in the session export). Mission format and rules: P§1.
